# FU ToDo · 业务规则说明

> 本文档解决什么问题：把《不用 App，分享一个适合低精力人群的计划方法》（B 站视频，作者羊清乐）提倡的纸笔计划方法，产品化为 Mac 应用「FU ToDo」。本文档固化阶段 1（业务流程图）确认的全部业务规则，作为阶段 2（产品结构图）、阶段 3（产品原型图）、阶段 4（开发）、阶段 5（测试）的共同依据。
>
> 读者：产品开发各阶段的执行者（本人），以及后续参与评审的人。
>
> 适用范围：业务规则层面；技术实现细节（数据模型、存储方案等）不在本文档范围。
>
> 需求用词分级：`必须` 表示强制要求，违反即不合规；`应当` 表示强烈建议，偏离需说明理由；`可以` 表示可选项；`暂不支持` 表示明确划出边界、防止范围蔓延。全文按此口径使用。
>
> 来源：原始资料 `Documents/知识库/AI知识库/原始资料 raw/不用 App，分享一个适合低精力人群的计划方法.md`（B 站视频 BV1a8346oExi）。

## 1. 产品定位与核心原则

产品定位：一个面向低精力人群的 Mac 每日计划应用，用极低摩擦的单目标计划代替复杂待办，帮助用户把 80% 的精力只投入 20% 最重要的事。

核心原则（均为 `必须`，源自原文方法，验收时逐条对照）：

1. **单目标优先**：每天聚焦「一件最重要的事」，其余事项不主动打扰、不散焦点。
2. **零摩擦启动**：打开应用即可写计划，无中间层级；精力再差也能用。
3. **不结转**：昨天未完成的任务不自动移到今天，靠大脑遗忘机制筛选重点。
4. **打开即专注**：界面只呈现当下与任务，不引入无关干扰。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 今日页 | 应用主界面，对应一个自然日，标题为当天日期 |
| 主目标 | 今日页里最重要的一个顶层任务 |
| 任务树 | 任务按树形结构组织：顶层任务下可挂多级子任务 |
| 勾选完成 | 点击任务左侧圆环完成任务 |
| 未完成池 | 展示状态为未完成的任务，可按本周 / 本月 / 所有筛选；界面文案显示为「未完成项目清单」，清单内标注任务所属日期并按日期降序 |
| 忽略 | 对未完成池任务执行「忽略」，任务标记完成（结束任务），决定不再做；界面文案显示为「结束」 |
| 重新执行 | 对未完成池任务执行「重新执行」，任务加入当天 |
| 已完成 | 任务结束状态；勾选完成（做到了）与忽略（放弃）都进入此状态；界面文案显示为「已结束项目清单」 |
| 撤销 / 恢复 | 把已完成任务退回未完成；撤销针对误点完成，恢复针对改变主意 |
| 月度回顾 | 月底对未完成池做批量整理（忽略或重新执行） |
| 跨天 | 新的一天开始，日页切换 |
| 主线 | 当天最重要的一件事；每天最多一个，显式标记，由应用保证唯一 |
| 支线 | 当天除主线之外的顶层任务 |
| 跨天移动 | 把任务（含整棵子步骤）主动移到另一天；不违背「不结转」——不自动结转，但允许手动搬 |

## 3. 业务对象与状态机

### 3.1 日期（Day）

一个自然日对应一个今日页；今日页为空白开始，旧任务不迁移（见 4.2）。

### 3.2 任务（Task）

任务为树形结构，字段如下：

| 字段 | 类型 | 是否必填 | 默认值 | 取值 |
|---|---|---|---|---|
| id | 字符串 | 必须 | 生成 | 唯一标识 |
| 标题 | 字符串 | 必须 | 无 | 非空 |
| 父任务 | 引用 | 可以 | 无 | 指向另一任务的 id；无父任务则为顶层任务 |
| 层级 | 整数 | 必须 | 1 | 1 表示顶层任务，向下递增 |
| 状态 | 枚举 | 必须 | 未完成 | 未完成 / 已完成 |
| 创建时间 | 时间 | 必须 | 当前时间 | — |
| 完成时间 | 时间 | 可以 | 无 | 进入已完成状态时写入 |
| 结束方式 | 枚举 | 可以 | 无 | 勾选完成 / 忽略；状态为已完成时记录，供月度回顾区分「做到了」与「放弃」 |

任务支持拖动调整层级与顺序（`必须`，用户已定）。

### 3.3 状态机

```text
未完成 --勾选完成--> 已完成
未完成 --忽略--> 已完成
已完成 --撤销 / 恢复--> 未完成
```

状态机如图 2 所示（`状态机图.html`，交互式图表，可缩放、切换明暗）。图中主流程箭头即「勾选完成」转移，底部通道为「忽略」与「撤销 / 恢复」双向边。

- 勾选完成：点击圆环；父任务完成时，整棵子树一并完成（`必须`）；叶子任务可独立完成。
- 忽略：对未完成池任务执行，任务标记完成（结束任务），决定不再做（`必须`）。
- 撤销 / 恢复（`必须`，用户已定）：恢复任何一层任务时，**只恢复这一条**，外加它上面的**关联链（上级）**——因为子步骤不可能挂在已结束的上级之下。它**自己的子步骤不恢复**，上级的**其他分支也不恢复**。需要整条一起退回时用「恢复这条及其子步骤」。
- 已完成与已归档合并为同一状态（用户决定，见第 7 节第 9 条）：「做到」与「放弃」的区别由结束方式字段记录，不占用状态。
- 忽略一个带子步骤的任务时，整棵子树一并结束（`必须`，用户已定，见第 7 节第 10 条）。
- 任务进入已完成状态后立即从今日页移出，仅保留撤销提示（`必须`，用户已定，见第 7 节第 11 条）。

## 4. 主流程规则

### 4.1 每日计划循环

1. 打开应用，进入今日页。
2. 若已跨天，应用自动开启新的一天（见 4.2）。
3. 写下今日最重要的一件事作为主目标（`应当`：界面引导只写一个主目标；`可以`：技术上限允许多个顶层任务，但非主目标的任务须以弱化方式呈现）。
4. 为主目标拆解子步骤（做完一步即可从今日页得知下一步）。
5. 逐步执行；中断或走神后回看今日页，定位当前步骤并继续。
6. 勾选完成（支持撤销）。

### 4.2 跨天

- 打开应用时检测日期变化，自动开启新的一天（`必须`）。
- 跨天 `必须` 全自动，**不提供手动按钮**（阶段 4 确认，覆盖第 4 条中的手动按钮部分）。触发时机：启动时检测、运行中每分钟轮询、窗口重新激活时检测（合盖过夜不会漏）。
- 昨日未完成的任务不迁移到今日页（`必须`），自动成为未完成池可查内容。

### 4.3 未完成池（非重点）处理

未完成池同时承担原文「便利贴」概念的非重点管理职能：产品不单设杂事区（用户决定，与原文方法存在差异，见第 7 节）。

- 入口：今日页上的「非重点」按钮。
- 内容：`必须` 只列**一级任务**（未完成、且所属日期在**今天之前**的顶层任务）；二级及以下跟着它的整棵树一起走，不单独列出（`必须`，用户已定）。
- 默认范围：`必须` 默认为「所有」，不隐藏任何未完成项（阶段 4 确认）。
- 范围基准：三档范围一律以**系统当前日期**为基准往回数——本周 = 7 天内，本月 = 30 天内，所有 = 不限（`必须`，用户已定）。未来的任务不算「没做完」，只在日历上属于它的那一天出现。
- 范围口径：「本周 / 本月」按任务创建日期距今的天数滚动计算（7 天 / 30 天），「所有」不做时间限制（`必须`，用户已定，见第 7 节第 12 条）。
- 操作一「忽略」：任务标记完成（结束），从未完成池移出；不物理删除，可在已结束视图撤销 / 恢复找回。
- 操作一之二「跳转」：跳到这条任务所在的那一天，并短暂高亮它，方便先看上下文再决定（`可以`，用户已定）。
- 操作二「重新执行」：把这条**以及它整棵树**搬到今天——原日子不再保留，已经完成的子步骤**保持完成状态**（`必须`，用户已定）。
- 同一天对同一任务重复点「重新执行」时去重，不再重复添加（`必须`，用户已定）。

### 4.4 层级结构与主线 / 支线

层级结构（`必须`，用户已定）：顶层可以有 **1 条主线（可选）+ N 条支线**；主线与支线都位于第 1 级，各自往下分第 2、3、…N 级。主线身份只是一个角色标记，`必须` 不改变层级——所以主线和支线可以并列、可以互相升降。

| 层级 | 内容 |
|---|---|
| 1 级 | 1 条主线（最多一条，可以没有）+ N 条支线 |
| 2 级 | 主线或支线的子步骤 |
| 3 级及以下 | 继续往下，层级由落点决定 |



- 每天 `必须` 最多一个主线；同一天再新增顶层任务时，只能落为支线（`必须`）。
- 主线 `必须` 只由用户显式指定：在主线栏写下、把任务拖到「今日主线」栏、或跨天时选择设为那天的主线。应用 `必须` 不自动产生、也不自动提拔主线（`必须`，用户已定）。角色的升降 `必须` 全部靠拖动完成，不额外提供按钮（阶段 4 确认）。
- 当天没有主线时 `必须` 也可以先添加支线（`必须`，用户已定）：支线入口任何时候都可用，主线栏同时提示「今天还没有主线」。
- 主线被完成或删除后 `必须` 不自动提拔支线，界面提示用户自己选一件设为主线（`必须`，用户已定）。
- 主线 `可以` 主动取消，降为支线（`可以`，用户已定）：一天允许没有主线。
- 主线 `必须` 是顶层任务；把主线拖成子步骤时，主线角色自动解除，当天回到「没有主线」状态。

### 4.5 主线与支线的规则

拖动 `必须` 带动整棵子步骤，落点决定结果：

| 拖动落点 | 结果 |
|---|---|
| 二级及以下的**左上半** | 成为该行的同级，排在它**前面** |
| 二级及以下的**左下半** | 成为该行的同级，排在它**后面** |
| 一级卡片**根行以外的区域** | 接进这张卡片：成为它的一步（整棵子树跟着进去） |
| 一级卡片之间（左上半 / 左下半） | 调整卡片顺序：插到它前面 / 后面，其它卡片自动让位 |
| 当天主线那一行的**左半边** | 设为今天的主线（主线栏里没有"同级"可言） |
| 行的**右半边** | 衔接：成为该行的子级（层级 = 该行的层级 + 1） |
| 栏内空白处 | 成为当天的一级任务（有主线时落为支线，没有主线时可以设为该天的主线） |
| 「今日主线」栏 | 设为当天主线（原主线降为支线） |
| 「今日支线」栏 | 作为支线（把主线降下来也走这里；主线可以没有） |
| 「今日完成」栏 | 直接完成（连带整棵子步骤） |
| 日历上的某一天 | 跨天移动：**整棵子树**移到那天（不是只搬当前这一条）；目标日已有主线则落为支线，目标日没有主线则直接成为那天的主线，**不再询问** |

新建任务的键盘约定（`必须`，用户已定）：**回车 = 在刚创建的那一条后面新建同级**，**Tab = 在刚创建的那一条下面新建下级**，`Esc` = 结束。

关键是**锚点跟着刚创建的那一条走**（对齐大纲编辑器）：

| 操作 | 结果 |
|---|---|
| 在 1 级上 Tab → 回车 | 创建它的 2 级子步骤 |
| 紧接着回车 | 仍停在该 2 级上，继续创建同级（**不会跳回 1 级**） |
| 再按 Tab → 回车 | 在上一条新建的 2 级下面创建 3 级 |
| 再回车 | 仍停在 3 级，继续创建同级 |

输入框会跟着锚点移动，所以能一直看到自己正在哪一条下面写。

**编辑与新建共用同一个输入状态**（`必须`，用户已定）：外观同款高亮、右下角同款按键提示、按键语义完全一致。

| 操作 | 新建时 | 编辑文字时 |
|---|---|---|
| 回车 | 在刚创建的那条后面继续新建同级 | 提交改动，并在这条后面继续新建同级 |
| Tab | 改成新建下级 | 提交改动，并在这条下面新建下级 |
| 点击任意空白 | 把正在写的落下去，然后结束 | 提交改动，然后结束 |
| `Esc` | 放弃这条，结束 | 放弃改动，结束 |

同一时刻 `必须` 只有一个输入框（正在编辑或正在新建）。进入编辑的点击目标是**整行**，不是文字本身（`必须`，用户已定）；从一条切到另一条时，`必须` 先把正在写的那条落下去，不能让内容丢失。

另外 `必须` 保证：不允许把任务拖进它自己的子步骤；移动后层级自动重算，拖走最后一个子步骤不会删除父任务。

### 4.6 拖动规则

- 每月底对未完成池做批量整理：忽略（标记完成）或重新执行（`必须`）。
- 产品应提供「被遗忘计划」的整理视图，让用户看到本月被遗忘、未完成的计划清单（`应当`）。

## 5. 边界情况

| 场景 | 规则 |
|---|---|
| 同日重复重新执行同一任务 | 去重，不重复添加 |
| 今日页无任何任务 | 保持空白可写状态，不显示任何提示性待办 |
| 恢复 N 级任务 | 只恢复这一条 + 上级链；它的子步骤与上级的其他分支保持已结束 |
| 恢复整棵（右键） | 这一条 + 它的全部子步骤一起退回未完成 |
| 已结束的父任务被恢复后 | 仍处已结束的子步骤不再重复出现在「今日完成」，但在「已结束项目清单」里仍能看到 |
| 已完成任务的查找与恢复 | 已完成仅隐藏，提供已结束视图，可撤销 / 恢复回未完成 |
| 勾选完成父任务时子任务未完成 | 子任务一并完成 |
| 忽略父任务时子任务未完成 | 子任务一并结束（整棵子树） |
| 已完成任务在今日页的呈现 | 立即移出，只保留撤销提示 |

## 6. 存储边界（阶段 4 起步约定）

- 数据本地存储起步（`必须`）：阶段 4 使用本地存储（SwiftData 或 JSON 文件）。
- iCloud 同步 `暂不支持`：明确不做首版，作为后续增强。

| 48 | 小图标的使用范围 | 角色小图标只在日历格子里标识主线/支线；日页不画图标（靠栏位 + 缩进 + 字号） |
| 47 | 卡片投放语义 | 拖到一级卡片上（根行以外）＝接进这张卡片成为它的一步；根行上下半＝卡片换位；主线那一行左半边＝设为今天的主线 |
| 46 | 支线一级拖到主线 | 变成主线的二级（它的二级顺延为三级）；不会因此变成主线 |
