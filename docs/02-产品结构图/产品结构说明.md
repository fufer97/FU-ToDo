# FU ToDo · 产品结构说明

> 本文档解决什么问题：把阶段 1 定案的业务规则，落成 Mac 应用「FU ToDo」的模块划分与模块间关系，作为阶段 3（产品原型图）、阶段 4（开发）、阶段 5（测试）的结构依据。
>
> 读者：产品开发各阶段的执行者（本人），以及后续参与评审的人。
>
> 适用范围：产品结构层面（功能区、模块职责、模块间关系）；界面布局与视觉细节属于阶段 3，技术实现属于阶段 4，均不在本文档范围。
>
> 需求用词分级：`必须` 表示强制要求，违反即不合规；`应当` 表示强烈建议，偏离需说明理由；`可以` 表示可选项；`暂不支持` 表示明确划出边界、防止范围蔓延。全文按此口径使用。
>
> 依据：`业务规则说明.md`（阶段 1，版本 0.2）。图示见 图 3（`产品结构图.html`，交互式图表）。

## 1. 结构总览

应用由四个功能区组成。按用户的使用顺序与职责划分：

| 功能区 | 职责 | 用户何时进入 |
|---|---|---|
| 今日视图 · 主界面 | 承载每日计划与执行 | 打开应用即进入 |
| 未完成池 · 非重点 | 承载非重点任务管理 | 点击「非重点」入口 |
| 已结束视图 | 承载已完成任务的找回 | 需要撤销 / 恢复时 |
| 数据与跨天 | 承载数据持久化与日期切换 | 后台自动，不直接展示 |

分区遵循两条原则（均为 `必须`）：

1. **单一入口**：打开应用后只有今日视图一个主界面，其他功能区都需要用户主动进入，不主动打断。
2. **职责不重叠**：未完成池只管「未完成任务的去留」，已结束视图只管「已完成任务的找回」，两者的数据来源与操作对象互不相交。

## 2. 模块清单

### 2.1 日历与日页 · 主界面

| 模块 | 职责 | 关键行为 | 规则依据 |
|---|---|---|---|
| 月历 | 一屏看到每一天计划了什么、做完了什么 | 一天一格，格子里直接显示那天的任务；点格子切换日页 | 4.1、4.2 |
| 日页 | 承载所选那一天的任务与执行 | 分「今日主线 / 今日支线 / 今日完成」三栏；空白开始，旧任务不结转 | 4.1、4.2 |
| 主目标 | 承载当天最重要的一件事 | 引导只写一个主目标，界面加重呈现 | 4.1 |
| 任务树 | 承载任务层级与执行 | 圆环勾选完成、拖拽调整层级与顺序 | 4.1、3.2 |

补充约定：

- 任务树 `必须` 支持多级子任务；勾选父任务时，整棵子树一并完成。
- 完成操作 `必须` 可撤销，撤销后子任务状态一并恢复。
- 顶层任务 `可以` 有多个，但界面 `应当` 引导只写一个主目标，其余顶层任务弱化呈现。
- 月历 `必须` 只读展示（不在月历上直接改任务），所有修改都在日页里完成。
- 日页 `必须` 分三栏：今日主线（当天最重要的一件事）、今日支线（次要的顶层任务）、今日完成（当天已完成的）。
- 任务标题 `必须` 可以点开直接改文字，不需要额外的编辑入口。
- 任务层级 `必须` 有一眼可分的视觉表达（见 2.5）。
- 日历里的时间方向 `必须` 一眼可分：**今天**用强调色；**已经过去**的日子用常规墨色；**还没到**的日子（今天之后）整格用浅灰——日期数字、任务文字、纸片底色一并压淡（阶段 4 确认）。

### 2.2 未完成池 · 非重点

| 模块 | 职责 | 关键行为 | 规则依据 |
|---|---|---|---|
| 未完成项目清单（规则名：未完成池） | 展示未完成任务并支持筛选；标注任务所属日期，按日期降序 | 按 本周 / 本月 / 所有 三个范围筛选 | 4.3 |
| 忽略 | 结束任务 | 任务标记完成，从未完成池移出 | 3.3、4.3 |
| 重新执行 | 让任务回到当天 | 任务加入当天；2 级（含）以下节点连带整棵未完成上级 | 4.3 |
| 月度回顾 | 月底批量整理 | 批量忽略或重新执行 | 4.4 |

补充约定：

- 同一天对同一任务重复点「重新执行」时 `必须` 去重。
- 未完成池 `必须` 承担原文「便利贴」的非重点管理职能，产品不单设杂事区。

### 2.3 已结束视图

| 模块 | 职责 | 关键行为 | 规则依据 |
|---|---|---|---|
| 已结束项目清单（规则名：已结束视图） | 展示已完成任务；标注日期，按日期降序 | 列表呈现，不物理删除 | 3.3 |
| 撤销 / 恢复 | 把任务退回未完成 | 撤销针对误点完成，恢复针对改变主意 | 3.3 |

补充约定：

- 已完成是唯一终点状态，勾选完成与忽略都进入它，两者区别由结束方式字段记录。
- 已结束视图 `必须` 提供找回入口，保证「结束」不等于「丢失」。

### 2.4 数据与跨天

| 模块 | 职责 | 关键行为 | 规则依据 |
|---|---|---|---|
| 本地存储 | 数据持久化 | 本地存储起步（SwiftData 或 JSON 文件） | 第 6 节 |
| 跨天检测 | 判断并开启新的一天 | 打开自动检测日期变化，另提供手动按钮 | 4.2 |

### 2.5 层级表达（`必须`）

任务层级不能只靠缩进表达。日页中的任务行同时使用五条线索，任一层级都能一眼区分：

| 线索 | 主线 | 支线 | 二级 | 三级 |
|---|---|---|---|---|
| 角色图标 | ◆ 菱形（强调色） | ● 实心圆 | □ 空心方 | ▪ 小方 |
| 字号字重 | 16.5 半粗 | 15 常规 | 13.5 常规 | 12.5 常规 |
| 字色 | 墨色 | 次墨色 | 次墨色 | 浅墨色 |
| 树线 | 无 | 无 | 1 级树线 | 2 级树线 |
| 缩进 | 0 | 0 | 22 | 44 |
| 完成圆环 | 18 | 18 | 15 | 13 |

角色图标 `必须` 用形状区分，不使用圆形——完成圆环已经是圆，再用圆会与它撞在一起。

层级结构 `必须` 是：顶层 = 1 条主线（最多一条，可以没有）+ N 条支线；主线与支线同为第 1 级，各自往下分第 2、3、…N 级；主线只是角色标记，不改变层级。

主线与支线是 `必须` 显式维护的角色，不是「列表里的第一条」这种隐式规则：每天最多一个主线；主线只由用户显式指定（主线栏书写、「设为主线」、跨天选择），应用不自动产生也不自动提拔；没有主线时同样可以先添加支线。

- 顶层任务之间 `必须` 有分隔，用来回答「哪些子步骤属于哪件事」。
- 树线 `必须` 在相邻行之间连续，形成从上到下的层级导轨。

**图标的使用范围**：角色小图标（◆ 主线 / ● 支线 / □ ▪ 层级）`必须` 只用在**日历格子**里标识主线与支线；日页不画图标——那里靠**栏位（今日主线 / 今日支线 / 今日完成）+ 缩进 + 字号**表达层级与角色。

### 2.6 动效约定

动效的作用是让状态变化被看见，不是装饰。全部短促、无弹跳，并 `必须` 尊重系统的「减少动态效果」（开启时一律取消动画）。

| 场景 | 动效 | 时长 / 曲线 |
|---|---|---|
| 悬停、按钮反馈 | 透明度与底色过渡 | 0.12s easeOut |
| 圆环打勾 / 撤销 | 填充 + 轻微放大回弹 | 弹簧 0.26s |
| 任务增删、层级移动、角色变化 | 位置与透明度过渡 | 弹簧 0.34s |
| 切换日期 / 切换视图 | 整体淡入淡出 | 0.26s easeInOut |
| 新建行展开 | 自上而下展开 + 淡入 | 弹簧 0.34s |
| 拖拽落点 | 插入线与高亮的淡入 | 0.12s easeOut |
| 底部提示条 | 自下而上滑入 + 淡入 | 弹簧 0.34s |

### 2.7 界面克制度

主界面 `必须` 不承载说明性文案，也不堆叠统计信息（阶段 4 确认）：

- 月历格子里只有日期与任务标题，不显示步数、条目计数等备注
- 分栏标题只写名称，不写「只写一件最重要的事」这类说明
- 清单弹层不写操作说明式的页脚
- 新建 / 编辑的输入行只保留占位符（「新任务」）与位置指示，不写「回车＝同级 · Tab＝下级」这类按键说明
- 操作说明放在独立的「使用说明」窗口（顶栏按钮打开），需要时去查，不在主界面反复出现

判断标准：这条文字是在帮用户当下做决定，还是只在解释产品？后者一律移出主界面。

### 2.8 字号表

全应用只用下面这几档，避免各处大小不一（阶段 4 定案）：

| 用途 | 字号 | 字重 |
|---|---|---|
| 日页日期 | 19（衬线） | semibold |
| 一级主线标题 | 15.5 | semibold |
| 一级支线标题 | 14.5 | regular |
| 二级 | 13 | regular |
| 三级及以下 | 12 | regular |
| 分栏标题（今日主线 / 支线 / 完成） | **15.5** | semibold + 字距 0.4 |
| 次要信息（日期、上级路径、计数） | 11 | regular |
| 按钮与控件 | 12.5 | medium |
| 输入框正文 | 13 | regular |

分栏标题属于"章"这一层，`必须` 与一级任务同档（当前都是 15.5），比正文大、颜色更淡（ink3），靠颜色和字距而不是靠缩小来区分层次。

### 2.9 字体规则

两档字体（设置 → 外观 → 字体）：

| 档位 | 标题声部 | 正文声部 |
|---|---|---|
| **纸墨** | **宋体**（Songti SC，粗体取 `Songti SC Bold`） | 系统无衬线（苹方） |
| **苹果风** | 系统无衬线（苹方 / SF） | 同上 |

**标题声部**指：日页日期、月历月份、**分栏标题（今日主线 / 支线 / 完成）**、卡片一级标题、清单页标题、设置页标题。二级及以下的正文一律用无衬线（小字号下宋体可读性差）。

⚠️ 实现注意：`Font.system(design: .serif)` 对**中文几乎无效**（会回退到同一款无衬线，只有数字和拉丁字变化），所以必须点名 `Songti SC` 这个中文字体，否则「纸墨」看不出差别。

### 2.10 配色的生效方式

配色/字体/字号变化 `必须` **立刻生效**，不允许"要重启才看到"。

做法：`ThemeSource`（通知源）由 `ThemeSync` 调用，**先着色再通知**——观察它的根视图在收到通知后重渲染，此时 `Theme` 已经是新配色。
反例（曾经的 bug）：在 `onChange` 里调用 `Theme.apply` —— `onChange` 在渲染**之后**才跑，而 `Theme.current` 是普通静态值不会触发重渲染，于是界面一直画旧色。

主题的 `.id(revision)` 会重建整棵子树：配色切换很少发生，这个代价可以接受。

### 2.11 配色的对比度底线

文字与控件的对比度 `必须` 达到下面的底线（阶段 4 按 craft floor 实测校正，浅色主题为例）：

纸面色调有五档，默认是**清爽**：浅灰底（#F5F6F7）+ 纯白卡片 + **品牌蓝**（#3370FF，选中态用 #E1E9FF）——参考现代协作工具（飞书）的克制语言：卡片靠 1px 描边而不是阴影，选中用浅色块 + 同色描边。其余为暖纸（朱红）、冷纸（靛蓝）、浅蓝、纯白（石墨）。默认字体是**苹果风**（苹方）。**墨色跟着纸色走**：冷色纸用冷调墨、暖色纸用暖调墨，避免冷纸上写暖灰发浑（阶段 4 确认）。

品牌蓝作为**填充**用 #3370FF（图形、按钮底色，≥3:1）；作为**文字**时换成更深的 #245BDB（纸色上 5.4:1），因为 #3370FF 写在浅底上只有 3.96:1。

| 用途 | 颜色 | 纸色上对比度 | 要求 |
|---|---|---|---|
| 标题 / 正文（ink） | #23211E | 13.0:1 | ≥4.5:1 ✅ |
| 次级文字（ink2） | #5C584F | 6.2:1 | ≥4.5:1 ✅ |
| 次要信息与提示（ink3） | #6F6857 | 4.9:1 | ≥4.5:1 ✅ |
| 强调（accent） | #B33D31 | 5.1:1 | ≥4.5:1 ✅ |
| 可交互控件描边（control） | #8F8A7A | 3.0:1 | ≥3:1 ✅ |
| **纯装饰（faint，不写文字）** | #A9A395 | 2.2:1 | 只可用于不需要阅读的图形 |

规则：**`faint` 禁止用于任何需要看清的文字**；占位文字与提示属于需要阅读的内容，一律用 `ink3`。

### 2.12 首次引导

第一次打开 `必须` 只弹一次引导（四句话：一天一件 / 点一下就改 / 拖动整理 / 不会堆积），
并提供「看完整说明」通往详细说明窗口；点过之后不再打扰，设置里可以重看。

引导讲的是**心智**，使用说明讲的是**操作**——两者不重复。

### 2.13 检查更新

设置 → 更新：`可以` 开关「启动时自动检查」，`可以` 手动「检查更新」。

- 实现：读取发布来源的 latest release 版本号，与当前版本逐段按**数字**比较（`0.10` 必须大于 `0.9`）
- 发现新版：只**提示版本号 + 打开下载页**；`禁止` 假装已是最新，也 `禁止` 静默失败
- **不做自动替换自身**：那需要稳定的代码签名身份（Sparkle 一类框架的前提），当前是 ad-hoc 签名 —— 做不到就如实说明
- 发布来源若是私有仓库，未认证请求会返回 404，界面 `必须` 如实提示「无法获取版本信息」

## 3. 模块间关系

图 3 中的六条连线与规则对应如下（图为阶段 2 版式，模块名以第 2 节的现行命名为准）：

| 连线 | 语义 | 规则依据 |
|---|---|---|
| 今日页 → 未完成池（非重点） | 「非重点」入口打开未完成池 | 4.3 |
| 重新执行 → 今日页（加入当天） | 任务回到当天任务列表 | 4.3 |
| 任务树 → 本地存储（读写任务） | 任务树的增删改查落到本地存储 | 第 6 节 |
| 跨天检测 → 今日页（开启新的一天） | 跨天时切换到新的空白今日页 | 4.2 |
| 忽略 → 已结束视图（结束进入已结束） | 忽略即结束，任务进入已完成状态 | 3.3、4.3 |
| 撤销 / 恢复 → 未完成池（退回未完成） | 已完成任务退回未完成状态 | 3.3 |

结构性结论（均为 `必须`）：

- 任务写入 `必须` 经过本地存储，界面模块不各自持有独立副本。
- 跨天 `必须` 由跨天检测统一触发，日页不自行判断日期。
- 未完成池与已结束视图之间的往返 `必须` 只经由忽略与撤销 / 恢复两个动作，不引入第三条路径。
