# FU ToDo · 产品原型说明

> 本文档解决什么问题：把阶段 2 定案的模块结构落成可点击的界面原型，明确每个界面的布局、交互细则与数据口径，作为阶段 4（开发）、阶段 5（测试）的界面依据。
>
> 读者：产品开发各阶段的执行者（本人），以及后续参与评审的人。
>
> 适用范围：界面结构与交互行为；视觉风格（配色、字体、动效）以原型为参考但 `可以` 调整；技术实现不在本文档范围。
>
> 需求用词分级：`必须` 表示强制要求，违反即不合规；`应当` 表示强烈建议，偏离需说明理由；`可以` 表示可选项；`暂不支持` 表示明确划出边界、防止范围蔓延。全文按此口径使用。
>
> 交付物：`产品原型.html`（可交互原型，双击用浏览器打开即可操作，无需安装任何东西）。
>
> 依据：`业务规则说明.md`（阶段 1，版本 0.2）、`产品结构说明.md`（阶段 2，版本 0.1）。

## 1. 怎么用这个原型

打开 `产品原型.html` 后，你会看到一个 Mac 应用窗口的模拟界面，里面预置了一份示例数据（一个主目标带三个子步骤、一封邮件、七条历史未完成任务、两条已结束任务）。可以直接操作：

| 想试什么 | 怎么做 |
|---|---|
| 完成一件事 | 点击任务左侧的圆环，父任务会连带整棵子步骤一起完成 |
| 撤销误操作 | 底部提示条上点「撤销」 |
| 调整层级与顺序 | 拖动任务行：拖到任务的上缘 / 下缘调整顺序，拖到任务中间变成它的子步骤；拖到底部输入框区域变回顶层 |
| 新增任务 | 在底部输入框写主目标（回车）；任务上点「+ 步骤」写子步骤（回车） |
| 看非重点 | 点右上角「非重点」或左下角入口，切换 本周 / 本月 / 所有 |
| 忽略或重新执行 | 在未完成池的任务行上点「忽略」或「重新执行」 |
| 找回已结束的任务 | 切到「已结束」，点「撤销完成」或「恢复」 |
| 模拟跨天 | 点右上角「开启新的一天」 |

## 2. 界面清单

原型共三个界面，对应阶段 2 的三个功能区分组。

### 2.1 今日页（默认界面）

自上而下：日期与「今天」说明 → 任务列表 → 底部新增输入 → 左下角「非重点」入口。

| 元素 | 规则 |
|---|---|
| 日期标题 | `必须` 显示当天日期与星期；副标题固定为「空白开始，旧任务不结转」 |
| 主目标 | 列表第一个顶层任务按主目标突出显示（字号更大、字重更重） |
| 其他顶层任务 | `必须` 弱化呈现（字号更小、颜色更淡） |
| 任务树 | 子步骤按层级缩进；`必须` 可展开收起（原型中完成即整棵移出） |
| 圆环 | 点击即完成；`必须` 连带整棵子步骤 |
| 底部输入 | 打开即可写；`应当` 保持空白可写状态，不显示任何提示性待办 |
| 非重点入口 | `必须` 常驻可见，带未完成数量角标 |

### 2.2 未完成池（非重点）

顶部为范围筛选（本周 / 本月 / 所有），下方为任务列表，每行有两个操作。

| 元素 | 规则 |
|---|---|
| 范围筛选 | `必须` 提供三档；默认「本周」 |
| 列表内容 | `必须` 只含未完成且不属于当天的任务；含子步骤（显示上级路径） |
| 忽略 | `必须` 结束任务（进入已完成状态），可撤销 / 恢复 |
| 重新执行 | `必须` 把任务加入当天；选中子步骤时连带整棵未完成上级 |
| 说明文案 | `应当` 在列表下方保留一行操作口径说明 |

### 2.3 已结束

按结束时间倒序列出已完成任务，每行标注结束方式并提供找回按钮。

| 元素 | 规则 |
|---|---|
| 结束方式标签 | `必须` 区分「勾选完成」与「忽略」 |
| 撤销完成 | 针对勾选完成的任务，`必须` 退回未完成 |
| 恢复 | 针对被忽略的任务，`必须` 退回未完成 |

## 3. 交互细则

| 交互 | 行为 | 规则依据 |
|---|---|---|
| 点击圆环完成 | 任务与整棵子树标记为已完成（结束方式＝勾选完成），从今日页移出 | 3.3、4.1 |
| 完成后撤销 | 任务与整棵子树恢复为未完成 | 3.3 |
| 拖拽到任务中间 | 该任务成为目标任务的最后一个子步骤 | 3.2 |
| 拖拽到任务上缘 / 下缘 | 在目标位置的同级中插入，调整顺序 | 3.2 |
| 拖拽到自己的子步骤上 | `必须` 拒绝，并提示不能拖进自己的子步骤 | 3.2 |
| 拖到顶层区域 | 任务升级为顶层任务 | 3.2 |
| 添加子步骤 | 在当前日期下创建子任务，层级自动递增 | 3.2 |
| 忽略 | 任务与整棵子树结束（结束方式＝忽略），从池中移出 | 3.3、4.3 |
| 重新执行 | 任务加入当天；若为 2 级及以下节点，连带整棵未完成上级加入 | 4.3 |
| 重复重新执行 | 当天已在清单中时不重复添加，仅提示 | 4.3 |
| 切换范围 | 按任务创建日期距今 7 天 / 30 天 / 不限过滤 | 4.3 |
| 开启新的一天 | 日期前进一天，今日页清空（不结转），未完成任务进入未完成池 | 4.2 |

## 4. 数据口径

原型使用内存数据，字段与阶段 1 的任务字段表一致，另加两个原型需要的辅助字段。

| 字段 | 含义 | 备注 |
|---|---|---|
| id | 任务唯一标识 | — |
| 标题 | 任务内容 | 非空 |
| 父任务 | 上级任务 id；为空即顶层 | — |
| 顺序 | 同级中的排序值 | 拖拽后重排 |
| 日期 | 任务所属的那一天 | 用于判断是否属于「今天」 |
| 状态 | 未完成 / 已完成 | 与阶段 1 一致 |
| 结束方式 | 勾选完成 / 忽略 | 与阶段 1 一致 |
| 结束时间 | 进入已完成状态的时间 | 用于已结束列表排序 |

三个界面的取数口径（`必须` 保持一致）：

1. 今日页 = 日期等于今天、且未完成的顶层任务，及其整棵子树。
2. 未完成池 = 未完成、且日期不是今天的任务，按范围筛选。
3. 已结束 = 状态为已完成的任务，按结束时间倒序。

## 8. 开发期形态变更（阶段 4 反馈）

阶段 4 动手做真实应用时，按用户反馈调整了主界面形态，`产品原型.html` 保留为阶段 3 的历史记录，不再同步维护：

| 变化 | 阶段 3 原型 | 阶段 4 实际形态 |
|---|---|---|
| 主界面 | 今日页单页 | 左侧月历（一天一格、格子里显示当天内容）+ 右侧所选日期的日页 |
| 未完成池 / 已结束 | 顶部标签页切换 | 独立弹层 |
| 层级表达 | 缩进 + 字号（偏弱，一级二级难区分） | 字号字重、字色、树线、缩进、圆环尺寸五条线索同时作用，顶层任务之间加分隔 |
| 视觉方向 | 中性浅色 | 「纸页台历」：暖纸底、墨色字、衬线日期、朱红只用于今天与进行中的事 |

开发期第二轮（按用户反馈）：
- 任务标题支持点击直接编辑（回车保存 / Esc 取消）。
- 行内「＋」改为常驻按钮，任意层级都能加子步骤（此前依赖悬停，二级行很难点中）。
- 右侧日页拆成三栏：今日主线 / 今日支线 / 今日完成。
- 「非重点」改名「未完成项目清单」，「已结束」改名「已结束项目清单」，清单内标注任务所属日期并按日期降序。

变更原因：用户反馈「一级二级三级关系不明显」「界面不好看」「希望有日历式界面，一天一个格子能看到每天的内容」。
