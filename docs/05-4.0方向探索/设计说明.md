# FU ToDo 4.0 · 方向探索说明

> 轮次：01　日期：2026-10-24　方法：oil-ui 方向探索流程
> 输入：用户对 2.0.4 的评价（功能/布局/UI/颜色 全部不满，60 分「勉强能用能看」），真实截图逐张分析，Things 3 真实画面标杆拆解。

## 一、现状诊断（2.0.4 三套主题的真实截图分析结论）

三套主题（标本室 / 器物 / 蓝图）病灶一致：

1. **隐喻停在贴纸层**：条码、REV.A、LIVE 圆点是「素材贴纸」，不是设计系统；排印功底（字号声部、线宽分级、对齐公差）没跟上。
2. **主线与支线同构**：主线卡和支线卡同尺寸同形式，「一天一件最重要的事」这一产品核心在视觉上不存在。
3. **布局失衡**：左栏月历空、右栏 460px 日页挤；卡片标题经常截断。
4. **日历格中文拦腰截断**：小格塞任务文本 + 「…」收尾，是全应用最难看的一处。
5. **灰字对比度踩线**：8-9px 淡灰文字多处在 WCAG 4.5:1 之下。
6. **装饰噪音**：同一套三件贴纸每张卡片重复出现，工具栏按钮规格不一。

## 二、标杆拆解（Things 3，真实画面）

「干净如纸」的具体做法：三栏 1:1.6:4；任务行零阴影零卡片、勾选框 18px 描边圆；行高 56-64px 的呼吸感；单一强调蓝只给「今天」与选中态（18px 高亮条 + 同色 2px 描边）；详情页是唯一白卡；列表层级只用字号字重，不用图标。
**取舍**：沿用其「层级=排印、强调色预算、克制」三条；换掉其三栏导航结构（本产品月历+日页双主体）与其配色身份。

## 三、调性（三方向共用，来自证据）

安静（每日面对的工具）· 精致（完成度是 60 分的核心抱怨）· 中偏疏 · 轻 · 中偏庄重。
所有候选在此调性内，只在骨架、色彩身份、主视觉上拉开。

### 关于 D「夜之城终端」（2026-10-24 应用户要求补充）

- **为什么它成立**：2077 本身就有「Main Job / Side Job / Gig（委托）」的任务结构，与产品的「主线 / 支线 / 未完成清单」逐位映射——隐喻是原生的，不需要贴纸（对照 2.0 的教训）。
- **做法纪律**：三级切角（面板 22px / 子面板 14px / 控件 6px）是组件语法不是装饰；黄色只给「今日与主线」（全屏唯一满色格是今天的日期块），青色=数据与交互，洋红只做未结标记；glitch 收敛为 1px 套印双色，保住可读性。
- **角色定位**：作为**第二主题**（夜间/心情皮肤），不替代 A 的默认身份；它验证了「排印日课的结构 + 换肤」的可行性——D 与 A 共用同一份内容结构（主线/支线/完成/月历/编号），证明主题系统可以保留。
- **实现注意**：D 要求深色外观，而当前 Theme.swift 强制 `NSAppearance.aqua`——主题系统需支持 per-theme 外观切换（设置 ThemeChoice 时同步切换 NSApplication.appearance）。
- 对比度检查残留：未来日期 2.68:1（刻意禁用态，同 A 的规则 #33）；左下终端读出行 9px（装饰性终端音，非信息）。

差异检验：三个首屏线框（纸页/工作台/桌面）明显不同；盲看感受「铅印日报 / 工程师工作台 / 摊开的便签」各异；C 最独特，B 最贴品类惯例，A 最接近文档排版（在待办品类里恰是空白）。D 为后补方向，见第四节。

## 五、选定：A「排印日课」（吸收 B 的两样发明）

**理由：**
1. 它正面解决根病——主线与支线的关系在这里是**字号声部**（40px vs 15px），产品核心「一天一件」第一次在视觉上成立；
2. 在待办品类里没有竞品这样做（品类内最不撞脸），且排印系统最不容易过时；
3. 实现风险最低（无材质、无阴影、无贴纸），SwiftUI 可高保真落地；
4. 吸收 B 的**编号定位系统**（01 / 01.1 / B-01 / A-01：树的地址，服务于键盘党与将来的快速跳转）与**密度历法纪律**（月历只放标记不放文字，中文永不截断）。

**朱砂纪律（全应用只有四处红）**：月历今日圈、主线方块、右下印章、输入态（光标与下划线）。计数、逾期、操作一律不红——「不惩罚」落在色彩语义上。

## 七、4.0 路线图（建议顺序）

1. **视觉系统移植**：按本说明第六节的令牌（纸 #FAF9F5 / 墨 #1A1A18 / 墨灰 #6E6960 / 朱砂 #C3402B / hairline rgba(26,26,24,.14)；字号表 42/40/15/13/12.5/10.5/9.5；宋体声部=日期+主线）重写 Theme.swift，单一主题，删三套卡片物种。
2. **结构改造**：日页改中轴排印页（主线=大标题声部）；月历改密度点阵（永不放文字）；页边编号系统进 Core（任务树地址 = 层级链 order 序列）。
3. **交互补课**：⌘N 快速新建（默认态已有 ghost 行）；编号跳转（⌘G 或 ⌘K 输 01.1 / B-02 直达）；月度整理批量化（评审 P2：多选 + 批量结束/重新执行）。
4. **后再议**：搜索/命令面板（以编号系统为基础回归）、进度感表达（「3/6」排印在日期行，不做进度条）。

## 十一、4.0 实现记录（2026-10-24 收尾）

4.0 已实现并发版（AppVersion 4.0，286 项自测）。与设计稿的差异与定案：

- **主线没有二级**（相比方向稿的重大变化）：方向稿的主线面板带 OBJECTIVES 目标列表，实现过程中用户改为「主线只有一个标题槽」——主线面板只剩黄标签 + DIN 标题 + 完成/退回按钮；不给＋下级、拖拽嵌套进主线被拒绝。二级只存在于支线。Core 仍允许主线有子树（旧数据兼容），UI 不再提供入口。
- **默认主题为夜之城**（用户定案），日课为第二主题；2.0 旧主题值迁移到夜之城。
- **左栏装饰**：经两轮对比页选型（A 电子标本/B 路网/C 监视器/D 雷达/E 数据雨/F 生物识别/G 频谱柱/H 星图/I 天际线），用户选定 E 演化为**旋转字符球**：130 个日/中/英/数混排字符按斐波那契球面散布，0.11rad/s 自转、15fps、前亮后暗、reduceMotion 静止；位置在月历下方（先后按用户要求上移/下移到中下段），列对齐月历网格后改为球体散布。
- **布局**：HUD 顶栏 + 左栏（242pt）+ 右侧三面板；主线标题槽紧贴 HUD，支线/已完成（1.35:1）拉伸到窗口底部、面板内滚动；点空白收输入会话。
- **输入流**（用户定案的大纲语义）：新建提交后刚创建的那条进入编辑态——回车＝新增同级（出现下一行输入框）、Tab＝新建下级；「新任务」空输入框与侧栏幽灵行互斥；主线标题的编辑提交不续接新建。
- 规则变更已回填 `../01-业务流程图/业务规则说明.md`（定案 73-80，版本 0.5）。
